HacXLerate · Technical project overview

Evidence-led investigation for digital brand risk.

SentinelX / Risk Radar is a modular application for triaging potential brand impersonation across URLs, domains, social identities, application listings, and user-submitted evidence. It is designed for brand protection analysts, security teams, and evaluators who need findings with traceable sources and visible uncertainty.

System architecture

One API-backed investigation and case workflow.

FastAPI exposes versioned APIs and serves static pages. Services compose evidence analyzers, provider adapters, persistence, and analysis stages. The browser calls those APIs; it does not reimplement investigation logic.

API and persistence

FastAPI and Pydantic contracts expose versioned endpoints. SQLAlchemy models and the configured SQLite or PostgreSQL database persist brands, submissions, cases, snapshots, monitoring checks, observations, and alerts.

Analysis services

Evidence analyzers, the official-asset exclusion gate, deterministic rule engine, optional scikit-learn scoring, correlation, investigator, and citation-validated RAG are composed in Python service modules.

Analyst interface

Static HTML, CSS, and vanilla JavaScript provide introduction, project overview, dashboard, investigation, monitoring, alerts, cases, reviews, and evaluation views. No frontend build step is required by this repository.

Evidence and assessment

Observations keep their source context.

The evidence pipeline records analyzer/provider provenance and explicit states for incomplete or unavailable work. The Stage 6 gate checks registered brand assets before detection steps. Rule findings include reasons and evidence references. The risk service combines rule and ML signals for prioritization; the result is a ranking score, not a calibrated probability or a verdict.

Grounded investigation and RAG

Investigator tools query stored submissions, brand assets, audit data, and configured discovery sources. RAG retrieves stored evidence and may include snippets from the one selected Brave, Tavily or Exa search provider. Snippets are labeled as snippets, result pages are not fetched, and generated claims must cite known retrieved document IDs. Unsupported claims are rejected or reported as partial.

Human decision stays explicit: cases, analyst reviews, reasons, and feedback labels are persisted separately from model and heuristic output.

Screenshot path

Image input is validated before optional analysis.

The image pipeline validates declared and decoded image format, bounds image size and dimensions, and then records available provider observations independently.

Implemented offline

Decode and evidence record

Pillow content decoding, MIME/format consistency checks, dimension limits, image hash, and API-to-case persistence path are covered by deterministic tests.

Optional provider

Local OCR

Tesseract support uses the optional Python OCR dependency and an operator-installed Tesseract executable. Neither pytesseract nor the executable is available in this verification environment, so real OCR was not exercised.

Not live-verified

Vision model

An optional Claude vision adapter records model output as an unverified visual observation. No Anthropic credential was configured and no live request was made. Model output does not authenticate a logo, person, profile, or brand.

Monitoring and alerts

Repeated checks are persisted, with provider limits visible.

Monitoring targets, bounded check intervals, execution records, provider status, observations, change alerts, acknowledgement, and case snapshots are persisted. The in-process scheduler is disabled by default; when enabled, configure a single scheduler-enabled application worker. A target is not shown as active until a provider check succeeds.

External discovery is not implied.
A monitoring lifecycle can run against configured providers, but this environment has no authorized social discovery provider. Unsupported or unavailable checks are recorded as unavailable. Provider failure does not mean the earlier evidence disappeared, and does not create a synthetic discovery or disappearance alert.
Security boundaries

Constrained collection and explicit trust boundaries.

Official asset exclusion

The server-side gate is evaluated before risk and alert analysis; clients cannot mark a candidate as alert-eligible to bypass the gate.

URL collection protections

Evidence URL validation and bounded request timeouts are part of collection. EVIDENCE_ENABLE_REDIRECTS defaults to false. These controls should not be interpreted as a claim that DNS rebinding is eliminated.

Untrusted inputs and outputs

Prompt instructions treat submitted material as untrusted. Search snippets and model observations remain attributed, and citation validation limits RAG claims to retrieved records.

External and optional integrations

Source includes adapters for URLhaus, OpenPhish, Brave Search, Tavily, Exa, Apple App Store lookup, Anthropic Claude, and optional local Tesseract OCR. Adapter presence is not a claim that credentials are configured, a provider is reachable, or a live response was verified. Search configuration exposes only key-presence booleans at /api/v1/providers/configuration.

The frontend is static and vanilla JavaScript. There is no package.json or frontend build system in this project.

Test methodology

Deterministic tests exercise local contracts.

Python tests use pytest, an isolated SQLite test database, injected provider fixtures, and mocked HTTP responses where external services would otherwise be required. Frontend helpers have Node tests and served JavaScript can be checked with Node syntax validation.

What these tests establish:
Contract behavior, state handling, persistence paths, evidence provenance, and expected provider failures under deterministic fixtures.

What they do not establish:
Live source coverage, production-scale reliability, detection accuracy on real adversarial data, OCR/model quality, or external service availability.
Future scope · Not implemented

Expand coverage only when it can be verified.
